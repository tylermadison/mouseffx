<Section id="contract" title="Effect contract">

An effect is a plain object with four functions and one number. It does not know about React, about the HUD, or about the other effects.

<Excerpt file="types.ts" region="effect-contract" lang="ts" page="architecture" />

- `init` gets a container element. The effect makes its own canvas (or canvases) and adds them to the container. It must not draw anywhere else.
- `update(dt, t)` runs one time for each frame. `dt` is the time step in seconds, and `t` is the simulation time. The effect does the physics and the drawing in this one call.
- `resize` gets the new viewport size in CSS px and the device pixel ratio.
- `dispose` removes the canvases and releases GPU resources. The three WebGL effects also force a context loss here, because browsers limit the number of live WebGL contexts.
- `count` is the number of simulated elements, for the statistics.

Each effect module is a singleton: `export default { … }` with its state on `this`. The sequence `init` → `dispose` → `init` on the same object must work, and it does, because `init` makes all state again.

</Section>

<Section id="pointer" title="Shared pointer">

All effects read one pointer object. It gives them the same view of the mouse, so an effect has no event listeners of its own.

### Autopilot

A background that freezes when the mouse stops looks broken. After 2.5 s with no `pointermove`, the pointer starts to follow a slow Lissajous path around a point a little above the screen centre. The change is eased over the next 2.5 s: `k` goes from 0 to 1, and the target is a blend of the path and the last real position. The first real movement sets `x, y` back to the mouse immediately.

<Excerpt file="pointer.ts" region="autopilot" lang="ts" page="architecture" />

### Velocity and smoothing

The raw velocity is the position difference divided by `dt`. A tab switch or a window focus change can move the pointer across the full screen in one frame, which is a velocity of 100,000 px/s or more. Effects that add pointer velocity to their physics (`fluid`, `gravity-well`, `ascii`) would explode, so the raw value is limited to 5000 px/s before the filter.

The two filters use `1 − e^(−dt · rate)` as the blend factor. This gives the same response time at all frame rates, which a fixed factor such as 0.2 does not.

<Section id="frame-loop" title="Frame loop">

One `requestAnimationFrame` loop drives the pointer and the active effect. It is outside React: no component renders for each frame. React state changes only when the effect changes, and two times for each second for the statistics.

<Excerpt file="controller.ts" region="frame-loop" lang="ts" page="architecture" />

- **Time step limit.** `dt` is limited to 0.05 s. After a long frame (garbage collection, a slow shader compile), an unlimited `dt` would put a large step into each physics integrator, and spring and gravity systems become unstable with large steps. Most effects limit their own step again to 1/30 s.
- **Pause while hidden.** Browsers stop `requestAnimationFrame` in hidden tabs, but they give a very large `dt` on the first frame after that. The loop thus stops on `visibilitychange`, and it sets `last` to the current time before it starts again, so the first step is a normal one.
- **Statistics.** `ms` is the CPU time of `update()` only. For the WebGL effects this is near zero, because the GPU does the work after the call returns. The frame rate is the more useful number for those effects.

</Section>

<Section id="loading" title="Selection and on-demand loading">

The catalogue (`catalogue.ts`) is plain data. The registry adds one literal `import()` for each effect, so the bundler makes one chunk for each effect, and one more for three.js. A visitor who looks only at `matrix` never downloads three.js.

<Excerpt file="controller.ts" region="select" lang="ts" page="architecture" />

Three details in `select` prevent defects that are hard to find:

- The `loading` flag drops a second selection while an import is in flight. Without it, two fast key presses can start two effects.
- `destroyed` is examined again **after** the `await`. React Strict Mode mounts, unmounts, and mounts again in development. The import of the first mount can resolve after its controller is destroyed, and it must not call `init` then.
- The previous effect is disposed, and the container is emptied, before the new `init`. If `init` throws, there is no current effect, the error text goes to the UI, and the next selection works.

</Section>

<Section id="resize" title="Resize and pixel ratio">

Resize events arrive many times for each second while the visitor drags a window edge. A resize makes new canvases or render targets, which is expensive, so the controller waits until 60 ms pass with no new event.

The controller limits the device pixel ratio to 2. Each effect can apply a lower limit: the WebGL effects use 1.5, and `nebula` also limits its internal width, because its cost is for each pixel.

<Section id="teardown" title="Teardown">

The first version of this project was a static page that never unmounted, and it had no teardown. In a React app the runtime must be able to go away fully: on navigation, in Strict Mode, and on Fast Refresh.

<Excerpt file="controller.ts" region="teardown" lang="ts" page="architecture" />

All listeners of the controller share one `AbortController` signal, and the pointer has its own. One `abort()` removes them all, so a new listener cannot be forgotten in the cleanup.

The controller lifetime is bound to the container **node**, not to a component. The `#fx` element has a ref callback that makes the controller and returns `destroy` as its cleanup. An earlier version made the controller in a `useEffect` of a parent component. A Fast Refresh then replaced the `#fx` node but did not run that effect again, and the controller drew into a node that was no longer in the document. With the ref callback, this condition cannot occur.

</Section>

<Section id="embedding" title="Embed one effect">

The modules in `src/lib/mousefx` have no React dependency. To put one effect behind a different site, copy that directory (the three.js effects need `three@0.160`), make a fixed full-viewport container with `pointer-events: none`, and drive the effect with your own loop:

```ts
import { createPointer } from './mousefx/pointer';
import fx from './mousefx/effects/fluid.js';

const container = document.getElementById('fx')!;
const pointer = createPointer();
fx.init({ container, pointer, width: innerWidth, height: innerHeight, dpr: devicePixelRatio, reduced: false });

let last = performance.now(), t = 0, raf = 0;
function frame(now: number) {
  raf = requestAnimationFrame(frame);
  const dt = Math.min(0.05, (now - last) / 1000); last = now; t += dt;
  pointer.update(dt, t);
  fx.update(dt, t);
}
raf = requestAnimationFrame(frame);

const onResize = () => fx.resize(innerWidth, innerHeight, devicePixelRatio);
addEventListener('resize', onResize);

// when the page or the component goes away:
function stop() {
  cancelAnimationFrame(raf);
  removeEventListener('resize', onResize);
  pointer.dispose();
  fx.dispose();
}
```

Or use `createController({ container, mode: 'fixed', effectId: 'fluid' })`, which adds the pause while hidden, the resize debounce, and the statistics, and returns `destroy()`.

</Section>
